1. Tổng quan

Lara-SCRM là CRM quản lý khách hàng và điều phối lead cho ngành y tế/dịch vụ. Mỗi khách chạy qua 7 phase lifecycle (từ "Thêm mới" đến "Sử dụng dịch vụ"), được xử lý bởi 4 vị trí (Trực Page → Tele → QL Sale → Sale) tùy theo 7 nguồn data khác nhau.

Hệ thống chia làm 2 tầng DB:

  • PostgreSQL (raw) — hứng lead thô từ mọi nguồn, schema JSONB linh hoạt.
  • MySQL (clean) — data đã chuẩn hóa, mọi nghiệp vụ chạy ở đây.

Pipeline job đọc raw → validate SĐT → check trùng → ghi sang MySQL. Chia số chỉ chạy sau khi lead sang tầng clean.

6. Rule bắt buộc (nghiệp vụ)

Booking-first (2026-07-31): chỉ được chuyển lead sang phase Sale khi booking_status = booked. Áp cho mọi role — kể cả sale/tele tự care khách của mình. Nếu chưa book mà bấm "Chuyển phase Sale" → DomainException throw, flash lỗi đỏ "Chưa đặt booking cho khách. Đặt booking xong mới được chuyển sang phase Sale."
Nguồn ↔ Role (SOURCE_PERMISSIONS): mỗi nguồn map với 1 permission cụ thể. Ai không có perm đó thì dropdown Nguồn sẽ disable option đó. Bypass duy nhất là lead.source_all (chỉ Admin cơ sở + Admin công ty có).
Ẩn filter "Chờ chia" theo perm:
  • "Chờ chia — Tele" chỉ hiện với role có lead.distribute_tele (CM Tele, CM sale, Team Leader, Admin cơ sở, Admin/DM).
  • "Chờ chia — Sale" chỉ hiện với lead.distribute_sale (CM sale, Team Leader, Admin cơ sở, Admin/DM).
Sale/Tele/Observer thấy filter chỉ có 3 option (in_care/booked/checkin).
Route gate (middleware EnsurePermission): mọi route đều gate bằng permission. Ví dụ /leads/create gate lead.create → Observer gõ URL sẽ 403. /reports gate report.view → Trực Page + Team Tele 403.
Imported_by scope: user tạo lead luôn giữ scope xem lead đó, kể cả sau khi engine chia cho sale khác. Trực Page vẫn thấy được lead mình up sau khi CM tele đã chia.
Assign sale trực tiếp (BOD/SA/BA):
  • User không có lead.distribute → tự động owner = chính user (sale tự nhận).
  • User có lead.distribute (CM/Admin) → bắt buộc chọn Sale nhận, không chọn thì error "bắt buộc chọn sale nhận".
Walk-in (WI): tạo mới → approval_status = pending. Cần role có lead.approve_source duyệt (CM sale, Admin cơ sở, Admin/DM) mới đi tiếp.
Data scope theo assignment:
  • SCOPE_SELF: chỉ lead mình là owner/receiver.
  • SCOPE_TEAM: toàn subtree của org_unit gán (Admin cơ sở dùng cái này — thấy toàn branch).
  • SCOPE_CUSTOM: chọn nhiều org_unit lẻ.

11. Tích hợp Sbooking (Phase C1)

Scrm ↔ lara-sbooking đồng bộ 2 chiều: scrm push booking → sbooking duyệt → callback về scrm; scrm pull master data (dịch vụ / phòng / bác sĩ / users) từ sbooking.

11.1 Cấu hình kết nối

Menu Thiết lập → Kết nối Booking (gate perm connection.manage). Nhập BOOKING_API_URL + BOOKING_API_TOKEN qua UI — AppServiceProvider override config('services.booking') từ AppSetting, ưu tiên DB hơn .env. Cột Sbooking co_so_id cạnh mỗi cơ sở HN/HCM/DN — map id cơ sở scrm ↔ sbooking, bắt buộc điền trước khi push booking.

11.2 Sync master data từ sbooking (pull)

LoạiNút UICLIModel scrm

Dropdown Dịch vụ / Thăm khám ở form Booking đọc từ sb_services (mirror sbooking) — không dùng bảng services nội bộ.

11.3 Push booking scrm → sbooking

  • Form booking ở lead-detail (Phase 4): chọn Loại / Cơ sở / BS / DV / ngày+giờ → status Đã xác nhận → Thêm booking. Chỉ status "Đã xác nhận" mới auto push.
  • SbookingClient::pushBooking gửi nguon = $lead->source_group (mkt/mkt_br/…) — không hardcode "SCRM" nữa.
  • Dropdown giờ đọc từ endpoint sbooking GET /api/sync/khung-gio?co_so_id=X khi user chọn cơ sở (Livewire hook updatedNewBookingFacilityId). Fail silent → fallback hardcode 8:30-12 / 13:30-18.
  • Sau khi push: local booking_log có badge "⏳ Đã gửi sbooking, chờ duyệt". Payload push kèm crm_khach_ma = code lead + nguon.
Rule chặn: nếu cơ sở chưa map sbooking_co_so_id hoặc user không chọn cơ sở → error đỏ, KHÔNG tạo booking local. Buộc admin cấu hình trước.

11.4 Callback duyệt từ sbooking → scrm

Admin sbooking bấm Duyệt / Bỏ duyệt / Từ chối → sbooking POST callback về scrm → badge dòng booking đổi:

  • Duyệt → "✅ Sbooking đã duyệt · id N", sync_status = confirmed.
  • Bỏ duyệt → về "⏳ Chờ duyệt", sync_status = synced.
  • Từ chối → "❌ Sbooking từ chối" + lý do.
Auth callback (2 hệ email khác domain): sbooking (@sweetsica.com / @59ntn.local) ↔ scrm (@longevity.com.vn) không map được user per-user → dùng shared token SCRM_API_TOKEN (cả 2 phía cùng giá trị). Middleware AuthByApiToken chấp nhận token này thay vì Sanctum per-user.

11.5 Sync booking sbooking → scrm (pull theo SĐT)

Khi mở lead có SĐT → syncBookingsFromExternal($phone) gọi GET /api/bookings?so_dien_thoai=X bên sbooking, upsert vào booking_logs theo sbooking_booking_id. Kéo cả booking do khách gọi thẳng sbooking (không qua scrm).

12. DevOps · Seed · CLI

Reset toàn bộ DB (local)

php artisan db:fresh-all — drop cả 2 connection mysql (clean) + pgsql (raw) rồi migrate:fresh --seed. Tránh lỗi "relation import_batches already exists" vì migrate:fresh mặc định chỉ drop default connection. Trên shared host thiếu quyền DROP SCHEMA — fallback drop từng bảng pgsql.

Seed sau reset

  • 0 khách hàng ảo — DemoDataSeeder + seedHoiLeads() đã comment out. Fresh seed sinh 83 users · 23 nhân sự trong scope admin.hn · 0 leads. Muốn có lead phải tự import hoặc tạo tay.
  • RolePermissionSyncSeeder — snapshot 14 role → perms lấy từ DB local làm source of truth. Sửa perm ở DB dev → chạy lệnh này để dump lại seed.
  • TeamHoiCustomFieldSeeder — 2 field "Phân loại" + "Kết quả" set required=false (để Tele fill phase 3, không bắt buộc lúc admin chia số phase 2).

Rename role tồn dư

Migration rename chạy trước seed, nếu seed cũ tạo lại role cũ trắng perm sẽ bug. Đã fix cho: Team booking → Team Tele (400e2a6), Team nhập lead → Trực Page (8ddd07c / 715115b). Nếu clone host cũ về thấy dropdown "Nhân viên phụ trách" phase Booking không hiện hn.book01/02 → chạy lại migrate:fresh --seed.

Fix chia số kẹt badge

  • poolAttributes chia số (person/org): set pipeline_status = IN_CARE ngay khi chia. Trước đây giữ WAITING → badge kẹt "Chờ CM booking chia" dù đã chia xong.
  • Dropdown chia số mở cho depth 4 (sub-team Booking/Sale) — có prefix ↳ Sub-team. Trước filter cứng ≤ depth 3 → sub-team Tele/Sale bị ẩn.
